# V2.1 implementation architecture

V2.1 extends the existing CAP/Express and React application on
`feature/toolsathi-v2-core`; the original trace algorithm and teammate adapters
remain intact. The V2 documents describe the earlier baseline; these documents
supersede their provider, localization and workforce limitations where noted.

Reasoning uses `srv/lib/reasoning.js`, a bounded Groq implementation of the existing
complete(messages, schema) interface. Sarvam still supplies STT/TTS through the
teammate client. Existing intake JSON validation, NC catalogue, provider error
handling, database transactions, audit/history and approval services are reused.

The persisted conversation stores worker/assistant turns, original language,
source-supported facts and draft metadata. The same endpoints serve voice and text.
Scope-filtered retrieval reuses the multilingual search/chunk/version infrastructure;
Groq generates answers only after authorization and retrieval.

Four additive workforce entities extend the prior 31-table model: WorkforceProfile,
WorkStation, ProductionDemand, TemporaryAssignment. The complete model compiles to
35 tables for SQLite and HANA. No original entity was altered. The direct HANA
destination received the 14 missing tables after explicit backup/update approval.
The verified full backup and all 585 original records were preserved.

New Manager workforce and Administrator system routes join the existing routers;
68 actual method/path handlers register without fallback stubs. OpenAPI includes
the new workforce/system contracts. `/health` reports actual database kind and a
non-secret instance fingerprint so saved frontend selection can be separated by
database context.

Frontend additions include the voice-agent state interface, redesigned floating
assistant, workforce capacity cards, system status and a record-backed investigation
timeline. Compile-time localization connects legacy JSX to checked-in static
Hindi/Kannada resources while preserving raw incident/report data expressions.

Production completion requires real identity-provider deployment and plant-approved
SOP/inspection metadata. Physical microphone testing
and native-speaker translation review are not claimed.
