# Windows startup and verification

```powershell
Set-Location C:\Users\yoges\Desktop\hackfest\SAP_HACKFEST
npm run dev:hana:v21
```

Open `http://localhost:5173/workspace`. This runs the approved, populated HANA
application with V2 workflows enabled; startup never deploys or seeds. If needed,
install dependencies with `npm --prefix backend ci` and `npm --prefix frontend ci`.
Set TOOLSATHI_BACKEND_PORT / TOOLSATHI_FRONTEND_PORT to use different free ports.

For an independent SQLite demonstration use `npm run dev:v21`, which creates a
new isolated local file with the synthetic graph. Plain `npm run dev` follows the
private environment without forcing V2 enablement. No command above overwrites it.

Worker: open Demo mode, select Worker with an explicit synthetic identity, select
equipment, choose Voice Agent or typed reporting, review transcript/facts and confirm.
Manager: select Manager, open an incident, review duplicates, select a qualified
technician and use existing separate restriction approval. Technician: accept,
record repair/readings and parts, then submit for Manager review. Verifier: use a
distinct identity to verify; incident closure remains explicit.

For workforce use Manager and incident `V21-INC-01`, Find available capacity,
inspect assumptions/exclusions, supply a reason and approve. Worker 03 is unqualified
for the proposed destinations. Return requires verified original equipment.
Fixture availability expires on 3 November 2026; after that, expired shifts are
correctly excluded. Changing the live fixture requires a separately reviewed update.

Use the named `V21-MANAGER`, `V21-TECH-2`, `V21-VERIFIER` and `V21-WORKER-01`
demo identities with their matching roles. The accepted conveyor work order belongs
to `V21-TECH-2` on `V21-INC-04`. Demo headers are local-development identity only;
production uses XSUAA and requires an actual configured identity-provider session.

The original Tool B HANA scenario is anchored at 4 November 2026, 05:12 UTC; the
local seed uses 31 October. Load synthetic demo report now reads the appropriate
clock from the connected database, instead of imposing a local hardcoded date.

The provider check spends bounded real provider calls with synthetic text only.

after explicit approval and verified backup. Do not use migration commands to start
the app. `node backend/scripts/v21-hana-verify.js` checks backup preservation, fixture
repeat preview, trace evidence and two backend starts without requesting remote writes.
