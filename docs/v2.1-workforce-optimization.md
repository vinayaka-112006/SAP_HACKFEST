# Workforce optimization

GET `/api/v2/incidents/:id/workforce` identifies workers by exact failed equipment
identity, not just a shared work center. Deterministic checks require an active
Worker profile, availability, matching skill/certification/safety authorization,
current certification, productive shift time, non-overlapping assignments, an
operational destination tool, materials, station slots and unallocated demand.

Recommendations rank deadline then estimated improvement. Productive minutes are
the smaller of requested duration and remaining shift, minus recorded setup time.
Output is floor(productive minutes / 60 × stored units/hour), capped by backlog
after output already allocated to active temporary assignments. The downtime
baseline is explicitly zero. This is an estimate from synthetic recorded inputs,
not a guaranteed production gain.

POST `/api/v2/incidents/:id/workforce/assign` requires Manager authority and a
reason, locks worker/station records, recomputes eligibility, persists the temporary
assignment, notification and application audit entry. Repeated matching requests
reuse the active assignment; overlapping work is excluded.

POST `/api/v2/workforce/:id/return` requires Manager review and the original tool
to be Active after existing safe-return verification. Restored equipment exposes
return candidates; no automatic shift or assignment change occurs. No AI can
override qualifications or capacity. Explanations currently show the recorded
deterministic assumptions directly; a separate live AI workforce explanation
capability is not claimed.

API and browser tests exercised disqualification, useful-output calculation,
approval, persistence, overlap prevention and reviewed return.
