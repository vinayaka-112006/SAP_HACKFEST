# V2.1 API additions

All routes retain existing identity, role and error conventions. See backend
OpenAPI and the regenerated `v2-api-contract.md` for request schemas. There are
68 actual registered method/path handlers. Manufacturing mock responses retain
their SIMULATED disclosure; real provider provenance is separate.

| Operation | Authority | Behavior |
|---|---|---|
| GET /api/v2/system | Manager, Administrator | Actual DB connection and configured/verified provider status |
| POST /api/v2/system/check | Administrator | Explicit bounded synthetic provider checks; audited |
| GET /api/v2/incidents/:id/workforce | Manager | Qualified recommendations, exclusions, assumptions, active/return candidates |
| POST /api/v2/incidents/:id/workforce/assign | Manager | workerId, stationId, minutes, reason; recheck/lock/persist/audit |
| POST /api/v2/workforce/:id/return | Manager | reason; restored source equipment required |

Existing conversation message requests additionally accept `reason: true` to run
Groq contextual extraction and follow-up generation. Session ownership/version
checks, explicit confirmation and retry semantics remain. `/ai/structure-report`
now selects the reasoning adapter and reports Groq provenance when used; speech
routes retain Sarvam and real MIME bytes. Chat requests add role-filtered retrieval
and source versions/citations before generation.

Health additionally reports databaseMode and a non-secret databaseInstance hash.
`GET /api/tools` additionally returns nullable `demoScenario`: synthetic-v1 fixture
time and provenance, verified against the stored seed audit and production runs.
This clock is used only when the user explicitly loads a synthetic report.
No API invokes migration or remote demo seed on normal application startup.
