# Localization implementation and coverage

The existing locale context remains. A compile-time Babel transform maps legacy
JSX static text/attributes and known label expressions into checked-in resources.
The transform runs only on application JSX, excludes the locale module and raw
style/code/pre content, and subscribes components to the existing locale context.
This avoids cloning pages, changing original report values or calling a model at
render time. Runtime lookups are static dictionary accesses.

`ui-source.json` contains 524 extracted interface strings; both Hindi and Kannada
resources are present. These resources were generated using Groq and checked for
completeness/encoding. Core workflow translations are maintained separately.
Native-speaker/domain translation review is still needed; generation and layout
checks are not represented as professional translation certification.

Language is persisted independently from reporting language. Original worker
statements remain untouched. Provider-returned source content and dynamic error,
record and audit text can remain in its original language; complete dynamic-content
translation is not claimed. Contextual strings assembled in utility functions may
also need further extraction despite the static JSX coverage.

Browser checks passed 5 main routes × 3 languages × 4 widths (375, 768, 1280, 1440),
including overflow assertions. Resource tests reject missing translations and
encoding replacement runs. Kannada/Hindi fonts remain bundled. No real-time
uncontrolled machine translation or fabricated translation fallback is used.
