Starting branch: `feature/toolsathi-v2-core`, commit `3e522fb` (clean).

## Phase A — confirmed baseline

Fresh baseline run: 33 backend suites / 282 tests; 34 frontend unit tests;
16 browser scenarios. All passed. Existing application has 68 API handlers,
35 CDS entities, XSUAA/invitation onboarding, conversations, qualification-based
repair assignment, scoped retrieval, parts reservations, manager review,
independent verification, manual workforce allocation and deterministic tracing.

Gaps confirmed in code: operational actions concentrated in `/workspace` with
manual incident IDs; no separate Manager/Technician/Verifier dashboards or
central issue detail route; no independent Assigner capability; no manager
work-center scoping; no correction/blocker workflow; no persisted notification
read markers; no multi-worker allocation execution or bounded automation policy;
no server PDF/CSV export; V21 demo shifts have fixed historical expiry dates.

## Implementation decisions

- Reuse existing `/v2` services and teammate AI/rules adapters. Never edit their
  owned folders or change deterministic trace calculations.
- Add related extension tables instead of altering the original 35 tables.
  Old HANA deployments remain usable until explicitly enabling the reviewed
  V22 schema. No startup migrations or HANA resets.
- Capabilities are approved server records, separate from identity-provider
  roles. Assigner is a capability on Verifier, not a self-selected new privilege.
- Legacy routes remain available. New pages use incident URLs and the existing
  client, speech component, workflow and exposure services.
- Functional screens and lifecycle tests precede visual polish. README is last.
